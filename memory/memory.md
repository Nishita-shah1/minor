# EchoLeaks memory

Updated 2026-09-26. Keep this a short status snapshot; `ARCHITECTURE.md` is the detailed handoff. Check current code before relying on dated experiment notes.

## Stack and built workflows

- Next.js 16.3.3 App Router, React 19, Tailwind v4, Clerk, Neon/PostgreSQL with Drizzle, private Cloudflare R2, Brevo, browser Web Crypto/libsodium/IndexedDB, PDF.js 6.3.289, ONNX Runtime Web 1.30.
- `/dashboard/upload` encrypts files locally (AES-256-GCM) and uploads ciphertext to R2. The owner RSA key is created on the device with no recovery-passphrase prompt; `components/crypto/key-vault-dialog.tsx` is removed. Full files are downloaded and decrypted in the browser; chunked streaming is not built.
- `components/dashboard/share-panel.tsx` adds up to 100 recipients to one batch per group and restores old links. Owner Send prepares encrypted key/fingerprint wrappers for enrolled recipients or an encrypted invitation grant for new recipients; Brevo email attempts are tracked per share. CSV/TXT/XLSX support here is recipient-list import only.
- Sharing uses the Profile OpenPGP public key in `user_openpgp_keys` (migration `0005`). Profile and share search (`components/crypto/sender-key-picker.tsx`, `GET /api/openpgp-keys/directory`) lists local GnuPG public keys plus published keys by name; fingerprint `70d29f3a9c351ba45636e3db27441b4377bfc9c9` is Gaurav. The browser encrypts document keys into `share_openpgp_envelopes` (migration `0006`). `/share/[shareId]` shows Add private key and hides the document until that private key yields its public key. A sealed share also requires the key to decrypt the grant. The private key is never stored.
- New recipients must sign in with the exact verified Clerk email, set up secure access, decrypt the invitation grant locally, and claim the existing share. `lib/shares/invitation-crypto.ts`, `lib/shares/claim-sql.ts`, and `app/api/shares/[shareId]/{invitation,claim,email}/` own this flow. Email provider acceptance is not delivery confirmation.
- `/share/[shareId]` shows the Clerk account control, checks recipient identity/schedule/status, and locally marks supported PDF pages or static PNG/JPEG before display. Recipients accept activity disclosure first; `hooks/use-viewing-session.ts` opens a session and posts bounded events. The viewer covers content on fullscreen exit, visibility/restoration, authorization loss, or marking failure; no clean fallback is displayed.
- `/dashboard` (`components/dashboard/dashboard-workspace.tsx`) is a live overview. `GET /api/owner/exposure-risk` returns documents, recipients, and viewing sessions. The page aggregates the selected range (7 days, 30 days, or all time) in `lib/activity/dashboard-metrics.ts`: files shared, recipients, view sessions, screenshot-shortcut attempts, print attempts, per-recipient last view, exposure risk, daily trend, and action breakdown. File names decrypt locally only when the device key vault is READY. `Unlock names` does not open a dialog. Until then the row says "Encrypted file". No hardcoded metrics.
- Exposure risk is a behavior-only heuristic (`lib/activity/exposure-risk.ts`, `lib/activity/owner-exposure.ts`). Screenshot counts are keyboard shortcuts the open page observed (`SCREENSHOT_ATTEMPTED`); phone photos and OS tools that swallow the key are not counted. Print uses `beforeprint`. It is not proof of a leak and is not merged with fingerprint Scan. Product overview: `WHAT-IS-ECHOLEAKS.md`.
- Viewing sessions: `viewing_sessions` + `session_events` (migration `0007`, after OpenPGP `0005` and `0006`). Recipient APIs: `app/api/shares/[shareId]/sessions/`. Client: `hooks/use-viewing-session.ts` after an activity disclosure. Estimated visible time: `lib/activity/visible-time.ts` (≤15s per interval; gaps >30s credit 0). Document deletion also deletes those sessions (`lib/server/delete-upload.ts`).
- `/dashboard/scan` automatically pages through owned encrypted fingerprint records, unwraps identifiers with the owner's key locally, decodes uploaded evidence locally, and shows name/email/share ID only for one exact match. `components/fingerprint/scan-workspace.tsx`, `copy-lookup.tsx`, `app/api/fingerprints/route.ts`.
- TrustMark Q/BCH_SUPER profile `trustmark-q-lab-v2` uses pinned ONNX assets and a browser worker with WebGPU or local WASM fallback. It is experimental and **not qualified**. `lib/fingerprint/`, `workers/fingerprint.worker.ts`, `scripts/prepare-fingerprint-assets.mjs`.
- Database tables and migrations are in `lib/db/schema.ts` and `drizzle/` (through `0007`: OpenPGP `0005`/`0006`, viewing sessions `0007`); `EXPERIMENTAL_FINGERPRINTING` is opt-in (`.env.example` defaults false). The local Neon migration/flag was previously approved; do not assume any other environment is migrated or enabled.
- Neobrutalist cream/yellow/black UI with rounded controls in `app/globals.css`; landing uses animated WebP for visible hero motion and optional native audio in `components/landing/hero-section.tsx`.
- Light/dark theme uses `next-themes`, Framer Motion, and `components/theme/`; the rounded toggle appears in the dashboard, landing/auth navigation, and share view. Scan shows a 100% indicator only for exact fingerprint ID equality, not recipient culpability.
- `components/dashboard/persistent-workspaces.tsx` retains visited Dashboard, Upload, Scan, History, and Profile UI in the current tab across route changes; Scan images/results, upload queues, drafts, and scroll positions clear on refresh, dashboard exit, or account/session change. History and recipient records refresh on return. `npm run test:workspace-state` uses synthetic local fixtures.
- Installable PWA: `app/manifest.ts`, `components/pwa/`, and `public/sw.js`; the landing shows an install card. The worker caches only public offline UI/icons, so account, sharing, and protected viewing still need a connection.

## Current limits and evidence

- Protected renderers: PDF all pages and static PNG/JPEG. Text, CSV, XLSX, DOCX, and phone-photo support are not built/qualified; XLSX import does not mean XLSX viewing.
- PNG/JPEG sources are bounded at 24 MP and 12,000 pixels per side, then fit to a marked surface bounded at 4,194,304 pixels and 4,096 per side. This can reduce detail; arbitrary resolution is not supported.
- Strength-1 synthetic tuning passed 18/18 in each full-page case but only 183/270 crops; 200 negative samples named no recipient. Half-size plus JPEG85 remains a failure. Human readability, held-out format-wide, blind multi-account, and physical-camera gates are missing. See `docs/fingerprinting/evidence/` and `ARCHITECTURE.md` before making reliability claims.
- Authenticated end-to-end invitation/email/view/scan has not been fully demonstrated. Intermittent Clerk lookup failures now return retryable, fail-closed 503s; their environmental cause is unconfirmed. Real Brevo delivery was not verified.
- Exposure risk is behavior-only and uncalibrated; hand-copying or phone photos can evade fingerprints. Deletion removes viewing sessions for erased documents; fingerprint rows still only while the experimental flag is enabled.
