# Domain docs

Use a single root `CONTEXT.md` and `docs/adr/`.

Before exploring, read existing context and relevant ADRs. If a future
`CONTEXT-MAP.md` exists, follow its links to the contexts relevant to the work.
Proceed silently when these files do not exist; create them lazily when domain
terms or architectural decisions are resolved.

Use the glossary's vocabulary. Surface conflicts with existing ADRs rather
than silently overriding them.
